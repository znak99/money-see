# 작업 관리 지침

## 목적과 기본 구조

`TASK.md`에서 프로젝트의 해야 할 작업과 완료된 작업을 함께 관리합니다. 설명은 한국어로 구체적으로 작성하여 시간이 지난 뒤에도 각 작업의 대상, 범위와 결과를 이해할 수 있도록 합니다.

기본 구역은 `미착수 작업`과 `완료된 작업`입니다. 미착수 작업 구역에는 진행 중인 작업도 포함합니다.

## 작업 식별과 설명

- 작업마다 `TASK-001` 형식의 고정 ID를 부여합니다. 전체 목록에서 가장 큰 ID의 다음 번호를 사용하며, 정렬하거나 완료 목록으로 이동해도 ID를 변경하지 않습니다.
- 목록 번호는 현재 정렬 순서를 나타냅니다. 항목 추가나 이동 후 번호를 다시 정리하며, ID와 혼동하지 않습니다.
- 제목에는 대상 플랫폼, 화면·기능 또는 문서와 수행할 내용을 구체적으로 작성합니다. "기능 구현", "문서 수정"처럼 작업을 구분하기 어려운 설명은 사용하지 않습니다.
- 필요한 상세 설명을 항목 아래에 작성합니다. 작업 범위, 결정할 사항, 선행 작업 등을 기록하여 어떤 작업인지 쉽게 파악할 수 있도록 합니다.
- 관련 커밋 메시지의 `변경` 항목에 TASK ID를 기록합니다.

## 정렬과 작업 등록

- 미착수 작업은 우선순위가 높은 순서로 배치합니다.
- 새 작업은 단순히 맨 아래에 추가하지 않고, 중요도와 선행 작업을 고려한 위치에 추가합니다.
- 완료된 작업은 완료 시점이 오래된 순서로 작성합니다. 새로 완료한 작업은 맨 아래에 추가합니다.
- 누락된 과거 완료 작업을 복원할 때는 새 ID를 부여하고, 확인 가능한 완료 날짜와 순서에 맞는 위치에 삽입합니다. 기존 ID는 변경하지 않습니다. 실제 완료일을 확인할 수 없다면 최초 관련 커밋 날짜 등 사용한 기준을 명시합니다.
- 사용자가 직접 지시한 작업이 목록에 없으면 먼저 ID와 구체적인 설명을 갖춘 항목으로 등록합니다.

## 작업 시작과 진행

1. 사용자의 작업 지시를 받으면 해당 작업을 찾거나 새로 등록합니다.
2. TASK.md의 해당 작업에 `[진행 중]`을 표시합니다.
3. 계획을 수립하고 사용자에게 구현 방침, 리스크와 결정할 사항을 설명합니다.
4. 별도의 개발 시작 지시를 받으면 구현과 검증을 수행합니다.

`[진행 중]`은 계획 수립부터 포함한 상태이며, 구현을 승인받았다는 뜻은 아닙니다. 단계별로 작업을 진행하거나 필수 검증이 실패한 경우 전체 작업이 완료될 때까지 이 상태를 유지합니다. 이어서 작업하는 데 필요한 진행 내용이나 문제를 설명에 남깁니다.

## 완료 처리와 Git 기록 순서

1. 구현 또는 문서 작성과 필요한 검증을 완료합니다.
2. TASK.md 변경을 제외한 작업 내용을 커밋합니다. 아직 push하지 않습니다.
3. 해당 작업을 완료 목록으로 이동하고 `[진행 중]` 표시를 제거합니다. 고정 ID는 유지합니다.
4. 완료한 내용이 드러나도록 설명을 정리하고, `완료일: YYYY-MM-DD`를 기록합니다. 날짜는 일본 시간 기준으로 작성합니다.
5. TASK.md 변경을 `Docs: [공통] ...` 형식의 별도 문서 커밋으로 기록합니다. 아직 기록되지 않은 작업 등록과 진행 표시 변경도 이 커밋에 포함합니다.
6. 작업 내용 커밋과 TASK.md 갱신 커밋을 함께 자동으로 push합니다.

- 위 완료 목록 이동 절차는 전체 작업이 완료된 경우에 적용합니다. 중간 단계의 커밋에서는 `[진행 중]` 상태를 유지하고 진행 내용을 갱신한 뒤 TASK.md를 별도 커밋하여 함께 push합니다.
- 점검·조사처럼 TASK.md 외에 변경한 파일이 없는 작업은 결과를 보고한 뒤 완료 목록으로 이동합니다. 작업 내용 커밋은 생략하고 TASK.md 완료 기록만 커밋하여 자동으로 push합니다.
- 필수 빌드·테스트가 실패하거나 실행하지 못했다면 완료 처리하지 않고 원인을 보고합니다. 문서만 변경했다면 문서 검토를 수행하고 빌드·테스트 대상이 없음을 기록합니다.
- 화면·애니메이션은 사용자 확인을 기다리지 않고 완료 목록으로 이동합니다. TASK.md에 `[사용자 확인 대기]`는 표시하지 않습니다.
- 완료 목록으로 이동한 것이 화면·애니메이션까지 사용자 확인을 마쳤다는 뜻은 아닙니다. 완료 보고에서 확인할 화면, 조작과 예상 표시·동작을 설명하고 미확인 사항을 명확히 알립니다.
- push에 실패하면 완료한 작업 기록은 유지하되, 원격 반영 실패 사실을 보고합니다.
- 상세 Git 규칙과 커밋 메시지 형식은 `GIT_STRATEGY.md`를 따릅니다.

## 기재 예시

아래는 형식 설명을 위한 예시이며 실제 작업 목록은 아닙니다.

```markdown
## 미착수 작업
1. TASK-002 [진행 중] iOS 월급 입력 화면에 입력값 저장 및 복원 기능 구현
   - 입력한 월급을 기기에 저장하고 앱 재실행 시 복원합니다.
   - 빈 입력과 잘못된 금액에 대한 일본어 안내를 제공합니다.
2. TASK-003 위젯·스마트 워치의 급여 표시 방식 설계
   - 플랫폼 제약을 확인한 뒤 표시 방식과 갱신 주기를 사용자와 논의합니다.

## 완료된 작업
1. TASK-001 Git 운영 지침 작성
   - develop 개발 및 main 릴리즈 운영, 커밋 메시지와 플랫폼별 태그 기준을 정의했습니다.
   - 완료일: 2026-10-02
```
